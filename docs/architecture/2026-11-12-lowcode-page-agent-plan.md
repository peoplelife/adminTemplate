# 低代码页面生成 Agent 计划

状态：Python Agent、Java 网关、前端工作区和 Redis 工作区持久化已实现并完成专项验证；数据库仅新增页面生成菜单初始化/增量脚本，未新增业务表。

## 目标

用户通过自然语言描述后台页面需求，Agent 生成符合现有前端模板规范的页面，并在右侧实时预览。首版关注“描述需求—澄清—预览—继续修改”这条主线。

## 前端模块

### 交互布局

采用固定的双栏工作区：

- 左侧为对话区，用户描述页面需求、回答 Agent 的澄清问题、继续提出修改要求。
- 右侧只保留页面预览区，展示当前生成页面的实际交互效果。
- 不设置会话列表。
- 不设置“页面生成 Agent”标题栏。
- 不设置“新建页面”按钮。
- 不在右侧展示源码、检查结果或版本标签。

用户需要生成另一个页面时，直接在对话中提出新的页面需求；页面描述和历史版本是否在后台保存，属于数据层设计，不在首版界面暴露管理入口。

### 对话组件复用

优先复用现有知识库问答页面的聊天组件，避免重新实现相同的交互：

- `MessageBubble`：复用用户消息、AI 消息、Markdown 渲染、复制、生成中和错误状态。
- `ChatInput`：复用多行输入、回车发送、发送按钮和禁用状态。
- 后续将公共聊天组件移动到 `frontend/src/components/ai/`，由知识库问答和页面生成 Agent 共同使用。
- 组件通过属性或插槽接收业务差异，不在公共组件中写入知识库或页面生成逻辑。
- 消息气泡需要支持自定义 Agent 状态文案，例如“正在分析页面需求”“正在生成页面”。
- 输入框需要支持自定义提示语，例如“描述你想生成的页面…”。
- 知识库参考来源作为知识库业务的扩展内容，不进入页面生成 Agent 的公共消息组件。
- 目前没有实际功能的附件、图片、语音按钮，页面生成 Agent 首版不展示。

### 页面预览

页面预览使用项目已有的公共组件和受约束的页面描述生成：

- 复用 `BaseTable`、`Form` 及已有基础控件。
- 使用合成数据展示搜索、分页、新增、编辑、删除、详情和表单校验。
- 页面预览不直接连接业务数据库。
- 模型只产生结构化页面描述，前端根据描述渲染模板组件，不能直接执行模型生成的任意代码。

### 首版明确不做

- 会话列表和会话管理入口。
- 新建页面入口。
- 源码查看器。
- 检查结果面板。
- 版本管理界面。
- 真实业务接口自动绑定。
- 附件、图片和语音输入。

## AI 模块

### Agent 职责

页面生成 Agent 使用公共 `answer_generation` 能力和 `default_model`，模型负责理解需求、选择下一步工具并生成结构化 `PageSpec`；代码负责校验 PageSpec、编译预览和限制可用组件。Agent 不直接执行模型生成的任意前端代码。

核心流程：

```text
用户消息
  ↓
理解需求
  ├─ 信息不足 → 返回澄清问题
  ├─ 查询模板用法 → search_template_docs
  ├─ 首次生成 → create_page_spec
  └─ 已有页面 → patch_page_spec
          ↓
      validate_page_spec
          ├─ 失败 → 自动修复一次
          └─ 成功 → compile_preview
                          ↓
                    返回文字回复和页面预览
```

### Agent 工具边界

当前提供以下受限工具：

- 读取模板组件能力；
- 搜索真实 BaseTable/Form 文档；
- 创建页面结构；
- 修改当前页面结构；
- 校验页面结构；
- 向用户提出澄清问题。

预览编译由创建和修改工具内部自动执行，不额外占用模型工具调用。

Agent 不执行 Shell，不读写任意服务器文件，不访问业务数据库，不自动绑定真实业务接口，不执行任意模型代码。

### PageSpec

PageSpec 是模型和前端之间的稳定协议，至少描述：

- 页面标识和标题；
- 字段名称、标签、类型和必填规则；
- 搜索字段；
- 下拉选项；
- 表单布局；
- 页面操作，例如新增、编辑、删除、详情。

PageSpec 使用严格结构校验。字段名、组件类型、操作类型和数量均有白名单限制。模型输出不直接作为 Vue/TSX 执行。

PageSpec 还包含 `table`、`pagination`、`form` 和 `sampleData`。字段可以声明 `column`、`attrs`、`defaultValue`；这些配置只映射到项目已有组件的白名单属性。示例数据最多 100 行，字段类型和选项值会校验，空数组表示空表。

### 状态和事件

左侧聊天组件接收通用消息事件，右侧预览只消费页面状态事件：

- `status`：正在分析需求、正在生成页面等状态；
- `message`：Agent 的文字回复增量，生成中逐段追加；
- `clarification`：需要用户确认的问题；
- `page_spec`：当前结构化页面描述；
- `preview`：根据 PageSpec 编译出的预览数据；
- `done`：本轮处理完成；
- `error`：本轮处理失败。

### 接口拆分原则

首版不暴露会话列表、新建页面、源码、检查结果和版本管理接口。界面上的单一工作区对应当前登录用户的工作状态；用户要求生成另一个页面时，由 Agent 直接替换当前 PageSpec。

建议首版接口按职责拆分：

- `GET /v1/ai/page-agent/workspace`：恢复当前用户的工作区、消息和当前 PageSpec；
- `POST /v1/ai/page-agent/messages/stream`：提交一条用户消息，以 SSE 返回 Agent 状态、文字回复、澄清问题和页面更新事件；
- `POST /v1/ai/page-agent/reset`：清空当前工作区，恢复为空页面状态；仅作为明确的重置操作，不作为“新建页面”入口。

页面预览中的搜索、分页、新增、编辑、删除和详情使用前端合成数据完成，不为这些交互增加后端接口。真实接口绑定留到后续阶段。

Java 继续作为认证和 AI 网关，向 Python 转发用户身份和 trace ID；Python 负责 Agent、PageSpec 和预览编译。两侧保持相同的请求、SSE 事件和错误字段契约，前端接口代码通过 OpenAPI 生成。

### 模型和错误处理

- 客户端不传模型时使用公共 `default_model`；
- Prompt 通过 `PromptRegistry` 管理，当前页面 Agent 使用 `page_generation@v2`；`v1` 保留为未改动的原始模板；
- PageSpec 校验失败自动修复一次，仍失败则返回明确错误；
- 模型、数据库和工具异常统一记录 `trace_id`、用户 ID 和工作区 ID；
- 日志不记录完整提示词、密钥或用户页面原文。

### 当前实现进度

已完成 Python AI 能力模块的第一阶段实现：

- `app/page_generation/schemas.py`：严格校验 `PageSpec`、字段、操作和 Agent 状态；
- `app/page_generation/tools.py`：实现组件读取、真实文档检索、页面创建、局部修改、校验和澄清工具，并从 Pydantic 结构生成禁止额外参数的 JSON Schema；
- `app/page_generation/documentation.py`：按标题分节检索 `frontend/docs/base-table-usage.md` 与 `form-usage.md`，开发环境读源码，镜像从命名构建上下文读取；
- `app/page_generation/compiler.py`：将 `PageSpec` 编译为使用合成数据的预览结构；
- `app/page_generation/agent.py`：使用 LangGraph 实现模型决策、工具调用、工具结果回放、澄清暂停、自动修复和步骤预算；
- `app/prompts/page_generation.py`：通过公共 `PromptRegistry` 注册 `page_generation@v1`；
- `app/answer_generation/service.py`、`app/llm/schemas.py` 和 OpenAI-compatible Provider：支持公共模型调用的工具参数、工具选择和结构化输出参数；
- 测试覆盖 PageSpec 校验、预览编译、工具边界、工具协议回放、空内容工具调用、错误修复和步骤上限。

本阶段已实现：

- FastAPI 页面 Agent 路由、用户隔离工作区和 SSE 契约；
- Java 网关转发、鉴权、可信用户身份和 trace ID；
- 前端双栏工作区、公共聊天组件和受约束的合成数据预览；
- 页面生成菜单的 fresh init 与 existing database 增量 SQL。

工作区使用公共 Redis，不新增业务表或独立数据库；以登录用户 ID 为键，闲置 7 天过期，保留最近 40 条消息，模型接收最近 20 条消息。重置会撤销当前生成令牌，迟到结果不能写回旧工作区。预览中的新增、编辑和删除仅修改浏览器内的合成数据，刷新或下一次页面更新会恢复合成快照。

本轮生成最多 180 秒，每 15 秒发送 SSE 注释心跳。浏览器断开时取消 Python 的待处理模型任务。只有工作区成功保存后才发出页面结果；前端只有收到成功的 `done` 才替换当前预览。

### 模型推理展示（2026-11-13）

页面 Agent 使用公共默认模型并显式启用思考模式，公共 Provider 独立解析 `reasoning_content`。LangGraph 在工具调用的后续请求中原样回传每轮助手推理，同时把增量通过独立 SSE `reasoning {content}` 传递到前端；`message` 继续表示正文，`status` 只更新当前工具状态。

公共聊天气泡提供可折叠“模型推理”，仅显示模型实际返回的内容，推理中展开、工具执行或回复及终止时折叠。正文与复制操作保持独立；内容按纯文本转义。工作区新增 `reasoningContent` 消息字段，在公共 Redis 中与正文分别保存，刷新可恢复，不新增数据库表。没有推理内容的普通对话不增加面板。
