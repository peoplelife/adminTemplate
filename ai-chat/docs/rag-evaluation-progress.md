## 第一阶段接口

内部前缀：`/api/v1/rag/evaluation-datasets`，沿用 `X-Service-Token`、`X-User-Id`、`X-Trace-Id`。

浏览器通过 Java `/v1/ai/evaluation-datasets` 访问同组接口，用户身份取自 JWT；不接受浏览器指定 owner_id。Java 列表参数为 `page / pageSize`，向 Python 转为 `page / page_size`。

| 方法 | 路径 | 功能 |
| --- | --- | --- |
| POST / GET | `/` | 创建/分页列出评测集 |
| PUT / DELETE | `/{dataset_id}` | 修改名称和说明/删除整个集及其历史 |
| POST / GET | `/{dataset_id}/cases` | 新增/分页列出样本 |
| PUT / DELETE | `/{dataset_id}/cases/{case_id}` | 修改/删除样本 |
| POST / GET | `/{dataset_id}/runs` | 同步执行/分页列出历史运行 |
| GET | `/{dataset_id}/runs/{run_id}` | 查看完整报告 |

列表请求为 `page / page_size`，响应为 `items / total / page / pageSize`，外层复用 ApiResponse。创建返回 201，删除返回 204。评测集建立后不支持更换知识库，避免原有依据失效；新知识库应创建新集。

样本示例：

```json
{
  "question": "入职半年能申请年假吗？",
  "category": "人事制度",
  "difficulty": "easy",
  "answerable": true,
  "expectedEvidence": [
    {"documentId": "文档 UUID", "text": "员工入职满一年后可享受带薪年假。"}
  ],
  "expectedAnswer": "暂时不能，需要入职满一年。",
  "notes": "依据使用原文，不绑定重建后会变化的 chunk ID"
}
```

运行请求：`{"topK": 5, "generateAnswers": true}`。默认关闭生成；开启后每题最多两次模型调用（生成、评审），均使用公共默认模型。参考答案用于正确性评分，未填写时正确性为 null；相关性和忠实性仍可评审。实际发给生成模型的上下文与正式对话一致，每条召回截取前 1200 字符。未加入未实现的 metadata_filter。

## 评分口径与限制

评分规则为 `evidence_contains@v2`：同一文档且去除空白、反引号后，召回片段包含整条依据才视为命中。每条依据最多计一次；单题 Hit 为是否命中至少一条，Recall 为命中依据数/标准依据数，MRR 为首个相关片段排名的倒数。运行指标是成功有答案题的宏平均；没有可评分题时为 null。历史报告保留原来的 `v1` 分数，新运行使用 `v2`。反引号不适用于需要区分该符号本身的代码语法题，此类题需另行制定标注口径。

这是一种可解释的自动筛查，不代表完整语义理解。跨 chunk 的依据、PDF 抽取差异和过长依据可能造成漏判；当前不猜测拼接、不进行语义裁判。标注时应选简短、完整、可定位的原文，后续接人工复核。

运行结束时原子保存报告和所有单题结果。最终保存前若任务取消或出现未处理异常，本次运行不会留下报告或假的 running 记录；未引入后台任务和恢复机制。前端评测请求与 Java 上游读取默认超时均为 60 秒，客户端超时不代表服务端一定已取消，应刷新历史确认，避免直接重复执行；现阶段先用小批样本。单题 AppException 可以记录为失败继续执行，未知代码/数据库异常由公共异常处理器记录并终止。

快照记录运行开始时的文档配置及每条实际召回 generation，但不会锁住整个知识库；评测期间应避免上传、重建或删除文档。严格固定语料版本的策略对比尚未实现。

报告包含私有原文，仅能由评测集所有者读取；不要把原文、完整问题、密钥写入日志。删除评测集会删除其样本和运行报告；单独删除样本只清空历史结果的 case_id，保留快照。
